# Systems Thinking Studio

Strategy-owned operating surface for converting verified systems evidence into
**staged, testable RIG intervention patterns**.

This is not an idea library. A mechanism is admitted only when it carries:

1. a source-gated L2 card hash;
2. a named system boundary and recurring behavior;
3. a transfer classification (`direct` or `structural`);
4. a concrete studio/process change;
5. a planted-failure-capable gate;
6. `STAGED_NOT_PROMOTED` state until an authority mutation is approved.

## Studio loop

```text
Observe → map boundary/state/delay → classify archetype
→ state intervention + counterfactual → shadow if costly
→ gate with planted failure → record evidence → learn / queue next gap
```

## Required intervention packet

| Field | Purpose |
|---|---|
| Boundary | What is in/out; owner and human override route. |
| State | Stocks, observers, sampling delay, and unknown-state behavior. |
| Archetype | Constraint, shifting burden, limits-to-growth, feedback delay, or competing explanation. |
| Intervention | Action, leverage point, expected causal outcome, and counterfactual. |
| WIP / queue | Work cap, queue-age signal, and drain condition. |
| Shadow | Baseline, prediction, divergence threshold, and rollout block. |
| Gate | Exact command/test, planted failure, restore condition, evidence path. |
| Approval | Action class, approver, scope, expiry, denial receipt. |
