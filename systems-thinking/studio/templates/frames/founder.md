# System Frame — Founder / operator (domain)

## 1. Boundary
- System of interest: one operator's attention → shipped money-making work
- Inside: calendar, A_ops cap, open loops, Gate-D
- Outside: family, gym, inbound chaos, agent fleet
- Boundary rationale: fleet size is not the system; operator attention is

## 5. Loops
- R1 polymath: curiosity → new project → progress high → more projects
- B1 jake-load: load over → pushback → no new starts
- R2 harvest: deals → proof → reputation → easier deals
- B_energy: late nights → skipped training → worse decisions → more late nights

## 6. Delays
start → finish: days to months. Feeling of progress is not the stock of finished.

## 7. Archetype suspects
`studio map "too many projects nothing shipping automation instead of selling"`
Typical: Shifting the Burden (automation theater) + Fixes that Fail (new project).

## 8. Leverage
Rank 12 (more agents) is the trap. Rank 6: greet/load numbers every session.
Rank 5: finish-before-start, Gate-D, kill dates. Rank 3: goal = governed machines that make money.

## 9. Measurement
- Health: open loops vs cap (25/40), A_ops min, recorded deals
- Lead: new starts today
- Falsifier: 14 days, deals still 0, open loops rising → R1 is eating R2
