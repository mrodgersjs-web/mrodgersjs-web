# How to Think Like a Rocket Scientist (Ozan Varol, book summary)

RCKT method: divergent reframing, backward planning, monkey-first validation, reality-adjacent testing.

## Procedure / models distilled
- Acronym RCKT (rocket without vowels) packages the four moves (0:42–0:49).
- **R — rethink what's possible**: swap "what *can* I do?" for "what *could* I do?" — "could" unlocks divergent thinking while "can" makes the brain scan old recipes (0:53–1:02).
- Idiot index: compare raw-material cost to final price; a huge gap signals outdated assumptions and inefficiency inflating the product (SpaceX rockets) (1:45–1:58).
- Practice: 20 minutes of "what could I do with the resources I have," ignoring everything you've been told won't work (2:05–2:24).
- **C — create checkpoints in reverse**: start from the finished mission (astronauts home safely) and walk backward — each checkpoint informs the one before it; this prevents overbuilding (2:27–3:13).
- Amazon's future press release: write the launch-day PR with customer quotes and FAQs first; every feature that doesn't serve the story gets cut (3:16–3:49).
- Personal version: write the end result in one sentence, list 5–7 checkpoints in reverse, and ask of any new task "checkpoint or detour?" (3:51–4:15).
- **K — kick off with the monkey**: in "train a monkey to recite Shakespeare on a pedestal," everyone builds the pedestal (easy, visible) while the make-or-break risk (the monkey talking) sits untouched (4:18–5:06).
- Identify the one hard thing to validate before investing more; set **kill criteria** — a dated result threshold that decides continue/abandon so you never over-invest in a doomed project (5:09–5:37).
- **T — test one step from reality**: NASA runs astronauts through ~6,800 malfunction scenarios so the real mission feels routine (5:42–6:04); Tim Ferriss picked his book title via real Google ad click-throughs and cover mockups on a bookstore table — strangers, not friends (6:05–6:39).
- Standing question: "how much more realistic can I make this test?" (6:58–7:03).

## Failure modes named
- Pedestal-building: spending project time on easy, visible, feels-productive tasks while the fatal assumption goes untested (4:46–5:06).
- Overbuilding from the start instead of deriving requirements backward from the end state (3:05–3:13).
- Testing on friendly audiences instead of reality (friends' opinions, living-room rehearsals) (6:41–6:58).
- Sinking costs into doomed projects for lack of kill criteria (5:31–5:37).

## Studio relevance
- leverage — validation sequencing: which assumption to kill first, tested one step from reality.
