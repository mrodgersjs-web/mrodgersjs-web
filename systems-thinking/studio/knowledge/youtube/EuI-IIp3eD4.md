# Systeme.io Automation Tutorial ✅ Setup Automation within Systeme Step-By-Step

A walkthrough of Systeme.io's two automation layers—simple funnel-level rules for beginners and the visual workflow builder for advanced, branching lead nurture logic.

## Procedure / models distilled
- Systeme.io provides two automation modes: "Rules" (simple list-style triggers at the funnel level) and "Workflows" (canvas-style builder with branching logic).
- Automation Rules are the fastest way to connect an opt-in page to a follow-up email campaign and a lead tag.
- To create a rule, open an opt-in page, go to the Automation Rules tab, click Add Rule, and set the trigger to "funnel step form subscribed."
- In a rule, chain an "add a tag" action to identify the lead source and a "subscribe to campaign" action to start an email sequence.
- The Automations > Rules page collects every rule across all funnels so you can view and filter them in one place.
- The Workflow Builder starts every new workflow as "inactive" by default and must be explicitly activated after completion.
- To build a workflow, set a trigger (e.g., "funnel form subscribed" on a specific opt-in page), then add actions such as tag, subscribe to campaign, send email, delay, webhook, or SMS.
- Use "decision" nodes in workflows to branch contacts based on behavior (e.g., clicked an email, opened an email, or received a specific tag).
- Map the "yes" path of a decision to a targeted action (e.g., a personalized email) and the "no" path to a follow-up or alternate action.
- Advanced workflow actions include creating a Google Sheet row, moving a contact to a pipeline stage, granting course or community access, notifying a team member by email, and sending webhooks or SMS.
- Add delays or "exact date" triggers inside workflows to time follow-ups relative to behavior or calendar events.
- Use automation rules for speed and simplicity; use workflows only when you need detailed, multi-path logic and have surplus time to optimize each lead.

## Failure modes named
- Forgetting to activate a workflow after building it, since the default status is inactive.
- Running the same automation through both Rules and Workflows simultaneously, duplicating tags, emails, or campaign subscriptions.
- Beginners choosing the workflow builder before mastering simpler automation rules and wasting time on unnecessary complexity.
- Building advanced branching logic without a clear plan for what the "yes" and "no" paths should deliver.
