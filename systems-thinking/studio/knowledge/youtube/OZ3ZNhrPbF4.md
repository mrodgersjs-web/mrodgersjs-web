# Build an Obsidian SYSTEM Not a Second Brain!

Eric Michaud argues that Obsidian should be built as a unified operating system for doing work—combining capture, metrics, reporting, AI agents, and execution inside one customizable dashboard—rather than a passive second brain or collection of disconnected workflows.

## Procedure / models distilled
- Treat Obsidian as a single work operating system where capture, reporting, intelligence, and execution all happen in one place.
- Build a daily dashboard that puts current focus front and center with a ranked to-do list, quick-capture inbox, shortcuts, and metrics views.
- Run a morning "today" agent command that auto-populates the daily note with calendar events, inbox items, and carryover priorities.
- Run an evening "close day" agent command that voice-dictates a daily review and fills the remaining metric properties.
- Track metrics as note properties inside a daily template, then visualize them with heatmaps, summaries, and overlapping graphs to correlate actions with outcomes.
- Log every activity performed inside the vault so the system captures its own behavioral trace.
- Embed external work surfaces such as email, Slack, Telegram, terminal, browser, and localhost inside Obsidian to eliminate app-switching.
- Use AI agents to feed inputs into the Obsidian structure while relying on Obsidian to close the agent's memory gaps.
- Convert captured notes into an active intelligence layer using custom plugins, dashboards, or canvas views instead of letting them accumulate.
- Anchor each day in a single daily note containing priorities, tasks, activity log, calendar, schedule, and metrics.
- Design custom views that show only what you need to focus on right now rather than generic metrics.
- Establish a consistent routine around the system; setup matters less than daily use.

## Failure modes named
- Believing capture is enough without reporting, intelligence, and execution.
- Building isolated workflows instead of an integrated system.
- Treating Obsidian as only a memory layer and building separate apps for metrics and monitoring.
- Asking "why not just use an AI with folders," missing the need for an operating system.
- Allowing constant app-switching and context-switching that drains momentum.
- Collecting notes until they become an unused graveyard.
- Treating flashy tutorials as isolated features to shelve instead of parts of a working system.
- Creating beautiful dashboards without actually using them daily.
- Scattering tools across multiple apps and interfaces, creating friction in search and reach.
