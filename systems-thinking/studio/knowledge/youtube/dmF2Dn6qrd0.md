# What is Fault Tree Analysis?

Fault tree analysis is a top-down, deductive method that builds a logic diagram of how lower-level events combine to cause an undesired top event, then quantifies probabilities to guide risk reduction and prioritization.

## Procedure / models distilled
- Define the top-level undesired event (accident, defect, equipment failure, hazard, or breakdown).
- Build the diagram downward from the top event using three symbol classes: events, gates, and transfers.
- Place intermediate events in the middle of the tree; these are caused by other events.
- Place basic events at the bottom as the most elemental factors causing the fault.
- Use gate symbols to represent the logical relationships between contributing events.
- Use transfer symbols to connect inputs and outputs of related fault trees, such as across multiple subsystems.
- Assign probability, reliability, safety, or quality values to the lowest-level events whenever data is available.
- Propagate the quantitative data upward to evaluate the probability of the top event occurring.
- Treat the completed fault tree as a visual model of the logical relationship between the unwanted event and its basic contributing events.
- Investigate how changes in the status of one or more system elements can combine to produce an accident, defect, or breakdown.
- Combine with bottom-up tools like FMEA to deepen analysis of failures identified as high-severity, frequent, or hard to detect.
- Apply within TPM, planned maintenance, and autonomous maintenance to understand equipment failure causes and risks.
- Use the finished analysis to visualize complex systems, quantify failure factors, and prioritize efforts that improve safety and reliability.

## Failure modes named
- accidents
- defects in product or process
- equipment failure
- potential hazards / risks
- breakdowns
- high-severity, frequent, or hard-to-detect failure modes (as surfaced by FMEA)
