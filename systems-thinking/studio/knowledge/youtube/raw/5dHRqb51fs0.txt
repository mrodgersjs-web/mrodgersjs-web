So, what's a loop?
A loop is a way for an agent to work autonomously towards a goal that you define.
Over the past few months, Codex, Claude Code, and Cursor have all shipped some form of automation support.
Claude Code calls them routines.
Codex and Cursor call them automations.
All three let you schedule prompts to run at a particular time.
Claude Code and Codex can run them locally or in the cloud, while Cursor runs them only in the cloud.
In the cloud, both Claude Code and Cursor can also be triggered by GitHub events or arbitrary webhooks.
Cursor takes this even further by allowing you to trigger automations on things like a Sentry issue opening
or a Linear issue being created, or changing states, and more.
All of these let your agent start acting proactively instead of waiting on you.
The next core piece of loops is the goal concept.
This is available in both Codex and Claude Code.
At the time of this recording, a first-party goal is not available in Cursor.
A goal lets you tell the agent what to work toward and then get out of the way.
Goals are great when you have a way to describe a definition of done for a particular task.
That can be a deterministic definition like all tests are passing,
or it can be something that the LLM infers.
Peter Steinberger shared a great example of this on X,
