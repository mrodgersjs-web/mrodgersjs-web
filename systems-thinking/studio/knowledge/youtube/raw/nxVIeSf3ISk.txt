The foundation of QEC is built on a
single uncompromising system law.
Identical inputs must inherently produce
identical outcomes. This absolute
certainty is enforced by translating raw
data into strictly ordered canonical
JSON payloads, which are then bound by
stable cryptographic hashes. There is no
room for approximation here. The system
categorically rejects probabilistic
matching, hidden state dependencies, or
fuzzy logic of any kind. By locking
these rules into place, QEC provides
mathematical certainty for
proof-carrying computation over graphs.
It turns executable code into
unforgivable law.
The existing V154.0
release established the foundation. It
successfully detects whole graph
structural matches and locks them into
canonical invariant patterns. However,
detection alone leaves a gap in the
semantic lattice pipeline. We lack a
rigorous mechanism to prove that these
materialized occurrences aggregate
consistently across explicit scale
boundaries. Traditional approaches rely
on recursive graph traversals or
implicit scale inferences. For this
specific problem, those methods are
computationally expensive and introduce
unacceptable ambiguity.
This flowchart maps the pipeline
geometry. We have V154.0 detection on
the left and future compression on the
right. To bridge this space, we
introduce the V154.1
update, a deterministic non-recursive
aggregation layer. The V154.1 layer
exists specifically to convert raw
structural matches into proof-carrying
receipts, eliminating the need to
re-evaluate or traverse the graph
multiple times.
Before aggregation can occur, the input
vectors must be locked. Release V154.1
introduces no changes to decoder
execution. It relies entirely on a
finite list of pre-materialized inputs
provided by the previous layer.
The first input is the subgraph
invariant pattern. This is a frozen
artifact containing a deterministic
pattern ID, a mathematically sorted node
label multiset, and strict constraint
edge pairs.
The second input is the subgraph
occurrence. This acts as the fundamental
vector binding the localized subgraph
match back to its parent pattern.
Every valid occurrence must bind
definitively to a deterministic pattern
ID. If the pattern identities do not
match, the input is immediately
rejected. Crucially, each occurrence
must also carry an explicit scale index.
The system does not guess or infer the
scale. It demands it as an explicit
parameter.
Notice the explicit scale index field in
these schemas, restricted to integers 0,
1, and 2.
QEC rigorously rejects booleans. True or
false inputs trigger a hard fail,
enforcing strict integer compliance.
Multiscale aggregation is mathematically
impossible without first guaranteeing
these strictly filtered, explicitly
scaled invariant occurrences. Once the
inputs are validated, we build the first
new artifact, the scale level summary.
This single data class acts as a
cryptographic container for one specific
observed scale.
Construction begins by filtering the
pre-materialized occurrences.
The algorithm selects only those that
match an exact pattern ID and a
non-boolean scale index.
From this refined pool, the system
exclusively extracts the individual
occurrence hash strings.
In this scale one data bucket, the
system extracts hex strings from raw
occurrences, forcing them into a
mathematically ascending sort.
A measurement bracket then calculates
the total occurrence count from the
exact integer length of that sorted
tuple.
To finalize the summary, we apply the
canonical payload principle.
This protocol governs how the localized
data is permanently sealed.
The sorted hashes, the integer count,
and the pattern ID are converted into a
stable canonical JSON serialization.
This serialization uses a self-excluding
format. The payload explicitly omits its
own future hash field, ensuring the data
tree does not create an infinite
recursive loop. Following equation one,
the isolated payload passes through a
SHA-256 computation to output the
definitive scale hash. The resulting
frozen artifact encapsulates the
structural evidence for a specific scale
layer. It contains zero hidden states
and zero external dependencies.
Individual scale layers must now be
bound together. The multi-scale
invariant receipt is the overarching
artifact designed to aggregate these
isolated summaries.
The constructor begins by globally
grouping all validated occurrences
according to their explicit scale index.
For every detected group, an independent
scale level summary is generated through
the exact deterministic steps we just
covered. The receipt enforces strict
structural geometry, stacking summaries
by ascending scale index. Here, scale
zero and scale two leave a deliberate
gap in the middle. Unobserved scales are
simply absent. There is no implicit data
insertion or empty placeholder for scale
one. Finally, the overarching
constructor sums the total occurrence
count across all valid layers,
generating a final receipt hash
utilizing the exact canonical payload
principle. The output is a single
mathematically rigorous hash. It binds
the verifiable existence of scale
separated patterns into one continuous
proof.
Creating the receipt is only half the
contract. During the validation phase,
structural trust is established
exclusively through dynamic
recomputation. The validator runs a
series of nested integrity checks. It
searches for duplicate indices, ensures
pattern IDs match exactly, and verifies
integer counts align perfectly. Consider
an isolated mutation. An adversary
alters the total occurrence count
integer in this nested JSON receipt,
leaving sub hashes untouched. The
validator forcibly compares the freshly
recomputed hash against the altered
stored hash. The discrepancy triggers an
immediate terminal value error. An
attacker might try to mask this by
simply copying a previously valid hash
field into the mutated structure. But
the self-excluding hash rules ensure the
math will fail to align with the forged
data payload. The invariant receipt
relies entirely on structural
cryptographic fidelity. Any data
tampering becomes mathematically
impossible to conceal.
