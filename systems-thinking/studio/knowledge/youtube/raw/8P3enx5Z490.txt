Okay, so let's talk about what's
actually under the hood because the
architecture is pretty clever. The brain
of the operation is Gemma 4 E2B. The E
stands for effective parameters, not the
total model size. The model technically
has more weights than 2 billion, but
only about 2 billion are active during
inference because of something called
per layer embeddings.
This trick lets the model stay small at
inference time while still keeping a lot
of knowledge baked in. It supports a
128k token context window, native
function calling, and handles 35 plus
languages out of the box. It's designed
specifically to run on phones, laptops,
and yes, browsers.
The extension actually uses two models,
not one. The first one is the Gemma 4
E2B instruct version. That's the
reasoning brain. It decides which tool
to call, generates the responses, and
runs the agent loop. The second model is
Mini LM L6 V2, which is a tiny embedding
model. It's only job is to convert text
into vectors so the extension can do
semantic search across your browsing
history and across pages you're reading.
So, when you ask the agent to find
something on the current page, it's not
just doing a keyword match, it's
actually understanding meaning.
Both models are quantized down to run on
consumer hardware. Gemma 4 uses Q4F16
quantization, which means the weights
are compressed to 4 bits with float 16
precision for activations. That's how
you get a model that would normally need
a workstation GPU to fit comfortably in
browser memory.
The whole thing runs through
transformers.js,
which is the JavaScript port of Hugging
Face's Python Transformers library. It
uses WebGPU for hardware acceleration,
so as long as your browser supports it,
you get GPU inference for free. The
architecture inside the extension is
split into three layers. There's a
background service worker that hosts the
models and runs the agent loop. There's
a side panel, which is the chat UI you
actually talk to. And there's a content
script that lives inside whatever
webpage you have open handling DOM
extraction and highlighting elements.
The reason for splitting things this way
is that Chrome's Manifest V3 has strict
rules about where heavy work can happen.
By keeping the model in the background
worker, the model only loads once no
matter how many tabs you have open. The
side panel and content scripts are kept
thin just sending messages back and
forth.
For the agent loop itself, Nico built a
tool calling layer he calls WebMCP,
which normalizes browser tools into a
shape the model can understand. Each
tool has a name, description, input
schema, and an execute function. When
you type a prompt, the model decides if
it needs a tool, emits a special tool
called token block, the parser pulls
that out, runs the actual function, then
feeds the result back to the model for
another turn. This loops until the model
has nothing left to call. The tools
available in the extension include get
open tabs, go to tab, open URL, close
tab, find history, ask website, and
highlight website element. Pretty
practical stuff for navigating the web.
